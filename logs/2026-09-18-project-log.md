# GS-NAV-Module 项目工作日志

**日期：** 2026-09-18  
**当日概况：** 完成应用功能模块化、DLIO 建图与地图保存完善、Nav2 与 SCAN-Planner 导航后端接入、点云转 LaserScan、点云定位模块接入，并在桌面应用中打通可自由组合定位与导航后端的完整启动流程。当天共形成 11 次提交。

## 1. 应用架构模块化

1. 将原先集中在 `qt_nav_node.py` 中的传感器、建图和进程管理逻辑拆分为独立模块，降低主窗口代码复杂度。
2. 新增 `features/sensors.py`，统一管理 Livox、RealSense 启停参数及实时数据订阅。
3. 新增 `features/mapping.py` 和 `ui/mapping_page.py`，将建图后端、ROS 接口、保存逻辑和 Qt 页面分层。
4. 新增通用 `ros_launch_process.py`，统一处理 ROS 2 launch 的日志、状态和完整进程组回收，供传感器、建图与导航系统复用。
5. 建立可扩展的建图后端注册结构，为后续接入其他 SLAM 算法保留统一接口。

## 2. DLIO 建图与地图保存完善

1. 新增独立建图页面，可选择点云与 IMU 话题，启动或停止 DLIO，并实时查看三维点云地图和 launch 日志。
2. 支持配置仿真时钟、RViz、地图输出话题、保存路径和体素大小，并通过 `/save_pcd` 保存建图结果。
3. 修复 DLIO 地图保存问题：支持传入完整 `.pcd` 文件路径，自动创建目标目录，并拒绝空地图或无效体素参数。
4. 地图文件名支持用户自定义前缀并自动附加毫秒级时间戳；遇到同名文件继续追加序号，避免覆盖已有地图。
5. 保存前检查是否已收到有效地图点云，保存完成后验证目标文件真实存在且非空，并在页面和日志中显示完整路径。

## 3. 地图文件统一管理

1. 新增 `map_storage.py`，集中处理地图默认目录、安全文件名和防覆盖命名规则。
2. 在线建图产生的 PCD、地图处理页面保存的 PCD，以及 Nav2 YAML/PGM 默认统一存放到 `src/gs_nav_map`。
3. 加载地图的文件窗口默认从统一地图目录打开；可通过 ROS 参数 `map_storage_dir` 或环境变量 `GS_NAV_MAP_DIR` 修改路径。
4. 地图处理页面增加地图名称输入，保存点云或栅格地图时自动生成唯一名称。
5. 今日已在统一目录形成 2 份 PCD 地图和 1 组 Nav2 YAML/PGM 栅格地图。

## 4. Nav2 导航栈接入

1. 将面向 ROS 2 Humble 的精简版 Navigation2 1.1.19 纳入 `src/gs_nav_navgation/nav2`。
2. 保留导航运行和二次开发所需的核心节点、消息接口、行为树、规划器、控制器、地图服务、生命周期管理及 RViz 插件。
3. 移除上游 Git/CI、容器、文档站点、测试、基准和 TurtleBot/Gazebo 示例资源，减少与当前项目无关的内容。
4. 扩展 `nav2_bringup` 启动文件，可通过参数选择是否启动 RViz，并指定 RViz 配置文件。

## 5. 点云转 LaserScan 功能接入

1. 新增 ROS 2 `pointcloud_to_laserscan` 包，将 MID360 的 `PointCloud2` 数据转换为 Nav2 可使用的 `/scan`。
2. 启动文件支持配置输入点云、输出扫描话题、目标坐标系、最低/最高高度、最小/最大量程和仿真时钟。
3. 默认输入为 `/livox/lidar/pointcloud`，输出为 `/scan`，目标坐标系为 `livox_frame`，满足后续导航避障链路的数据需求。

## 6. 点云定位模块接入

1. 新增 ICP Registration、Localizer、定位服务接口和手动重定位工具，并引入 FastGICP、NDT-OMP、Scan Context 等相关实现。
2. Localizer 支持加载 PCD 定位地图，订阅 DLIO 去畸变点云及里程计，并通过点云匹配估计地图坐标系下的位置。
3. 增加定位配置、Scan Context 数据库、RViz 配置及地图保存、重定位、地图优化等服务接口。
4. Localizer 启动文件新增地图路径、点云话题、里程计话题和配置文件覆盖参数，便于由上层界面统一调用。
5. 更新默认地图与 Scan Context 数据库路径，使其指向当前 `GS-NAV-Module` 工作空间。

## 7. 完整导航流程打通

1. 在桌面应用中新增“导航系统”页面，将完整运行链路按依赖顺序统一启动：Livox MID360、RealSense D435i、DLIO、PointCloud2 转 LaserScan、Localizer、Nav2 Bringup。
2. 启动前检查 Nav2 YAML 地图、Localizer PCD 地图、可选参数文件及 LaserScan 高度和量程配置，防止错误配置进入运行阶段。
3. 雷达与相机不再只根据进程或话题名称判断可用，而是等待真实消息到达；超时或数据中断时会停止后续启动并给出诊断信息。
4. 已由传感器管理页启动或已检测到真实数据的设备会跳过重复启动，避免同时拉起多个相同驱动。
5. 任一中间组件启动失败或异常退出都会中止启动队列；整套系统可按反向顺序停止并回收软件管理的全部进程。
6. 系统及六个组件分别提供状态与日志视图，日志可跨页面保留，并与传感器管理页同步相关诊断信息。
7. 软件只清理由自身管理的进程，不会强制结束用户从外部终端自行启动的节点。

## 8. SCAN-Planner 导航后端接入

1. 新增面向 ROS 2 Humble 和 C++17 的精简版 SCAN-Planner，保留局部规划、局部建图、闭环速度控制和 RViz 调试能力。
2. 规划流程包含滑动局部栅格、动态 A* 路径搜索、B-spline 轨迹优化和碰撞检测，可输出 B-spline 轨迹及调试点云和 Marker。
3. 感知输入可在激光点云和深度图之间选择，支持原始传感器坐标点云或已经转换到世界坐标系的点云。
4. 支持三种导航模式：单目标导航、参数文件多途径点导航、沿外部参考路径局部规划。
5. 提供可选闭环控制器，将 B-spline 轨迹转换为 `/cmd_vel`；若底盘已有轨迹控制器，可关闭内置控制器并直接消费轨迹。
6. 精简掉 Gazebo、地图生成、传感器渲染、机器人模型和运动学仿真等非实机运行内容，聚焦当前导航项目需要的模块。

## 9. 定位与导航后端可插拔改造

1. 新增 `navigation_backends.py`，将具体定位和导航算法从启动流程控制器中解耦，统一负责参数校验与 launch 命令生成。
2. 定位后端支持“点云 Localizer”“不启动定位”和“自定义定位 Launch”；导航后端支持“Nav2”“SCAN-Planner”和“自定义导航 Launch”。
3. 默认组合仍为 Localizer + Nav2；选择“不启动定位 + SCAN-Planner”时，可直接使用 LIO 里程计和点云，不再强制要求 PCD 或 YAML 地图。
4. 导航系统参数界面拆分为“地图、定位、导航、DLIO、LaserScan、通用”六个页签，各后端只展示自身相关配置。
5. SCAN-Planner 页面可配置导航模式、感知类型、里程计/点云/深度图/目标/参考路径/速度话题、控制器、坐标约定、外参和参数文件。
6. 自定义后端支持填写任意 ROS 包、launch 文件和附加参数，并支持地图、配置、参数文件和仿真时间占位符。
7. 启动控制器会自动跳过禁用的定位阶段，状态面板明确显示“已禁用”，其余组件仍按依赖顺序启动和回收。
